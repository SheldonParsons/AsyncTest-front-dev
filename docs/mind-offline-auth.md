# 思维导图离线与认证边界

## 本次定位

- 旧 UI 将“本地还有 token”直接当作已登录，未检查服务端是否已撤销或过期。
- 个人资料请求经过全局认证跳转；在 `/mind` 中遇到认证失败时会跳到 dashboard，导致思维导图组件和关闭监听卸载。
- 新窗口首次路由解析前可能短暂挂载主 header，产生原本不属于本地编辑器的资料请求。
- 主进程仍等待思维导图渲染器的关闭确认；旧逻辑等待 60 秒后只取消关闭，没有可见恢复操作。此链路可解释窗口错页及关不掉，但未获得 Windows 用户日志，不能认定已覆盖该用户所有卡死原因。

## 修复后的行为

- 区分未验证、验证中、已认证、认证失效、服务不可达。本地 token 存在不代表服务器已确认登录。
- 主窗口启动时在后台检查资料；不持有 token 时跳过请求。资料请求最多等待 5 秒，不触发整页导航。
- 明确认证失效时清除本地认证并同步其他窗口；断网不删除凭证，也不显示成密码错误。旧请求的失效响应不能撤销后来登录的新凭证。
- `/mind`、`/mindDashboard` 及 mind 窗口不因登录失效或退出广播跳转。
- 思维导图启动、打开、编辑、本地保存和关闭均不依赖资料请求；本地保存即使存在项目远程绑定也不自动上传。无本地保存路径时使用本地另存为。
- 用户点击分享／上传时检查认证。未登录弹登录窗，服务器不可达提示离线上传不可用；本地文件、内容及路由继续保留。
- 首个路由解析完成后才挂载 header，避免新窗口闪现 dashboard 身份并触发资料请求。
- 关闭请求 10 秒未响应时出现原生选择框；用户可继续等待或明确关闭窗口。不会无提示丢弃未保存内容。正常保存／取消关闭流程保留。

## 验证与限制

外部验证源码：`ast-testing-core/suites/mind_offline/`。数据与日志：`ast-testing-core-data/runs/mind-offline/`。

真实 macOS Electron 验证了无 token、过期 token、网络不可达三种场景：本地 .amind 打开、编辑、保存到磁盘、不隐式上传、显式分享检查、保持思维导图路由、正常关闭。另将窗口故意导航为 dashboard，验证丢失关闭监听后的原生关闭恢复。

合约测试验证本地保存不调用远程写入、旧认证响应不撤销新会话，以及模拟 `win32` 的 WindowManager 创建和关闭分支。这不是 Windows 真机验收；仍需反馈应用版本、文件格式及日志，以确认该用户的现象是否还包含其他 Windows 专属问题。
