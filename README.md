# AsyncTest 桌面端与前端

## 开发与验证

- 使用 Node >=22.19.0 和 yarn；完整桌面开发入口是 `yarn electron:dev`。
- `yarn dev:electron` 仅启动 3333 上的 Renderer，单独运行它不会启动 Electron。
- `yarn build` 只构建；类型检查单独执行 `yarn vue-tsc --noEmit`。不要把构建成功当成全量类型检查通过。
- 测试由项目外 /Users/sheldon/Documents/AsyncTest/ast-testing-core 持有，数据和证据在其同级 ast-testing-core-data；不把测试资产提交到产品仓库。

## 知识录入正文所有权

- 整理是桌面 Agent 的正常任务，通过服务端唯一 Skill 和工具目录指导；不增加前端美化引擎，不让知识库再次自动改写。用户要求原样时跳过整理。
- 长材料可用已有本机工具分段读取、写出 UTF-8 结果，再通过新增/完整替换的 `content_file` 提交。子进程读取并冻结文字，Main 复用现有分块/hash 传输；知识写接口只接收字符串，不接收路径。
- 文件读取仅接受绝对路径、普通 UTF-8 文本，检查并发变更；单文件/单批文件内容最多 4 MB，失败不截断。与原生本机工具共用操作系统权限边界，无新增特权读取。
- 完整正文预览、现行内容差异、确认、取消、冷恢复和回执沿用原有链路。新请求不提供后端“改用原文美化”选项，历史已生成预览仍兼容。
- 前后端需配套更新；无新依赖或数据库迁移。测试继续使用项目外 `ast-testing-core`。

## 模型请求期限

运行快照 timeout_ms 限制单次模型响应（包括流式正文）；max_wall_clock_ms 的剩余额度也约束当前模型流，等待用户确认不计入。超时按失败报告，手动停止按取消报告；不会因超时自动重放知识写入。
